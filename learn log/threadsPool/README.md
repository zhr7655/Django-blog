基本模型：任务队列与线程池
    任务队列存储待处理的任务，线程池存储线程，每个线程不断从队列中取出任务进行处理
    关于互斥锁：互斥锁是加在队列操作上的"锁"，作用就是防止多个线程同时对任务队列进行操作，进而导致数据错乱
                强行使并行操作变成串行，但是也导致了一定的性能下降。
                注意：在两个任务处理同一个数据时，也应该给数据上锁，不然会出现问题
    关于线程池：线程分为核心线程与暂时创造的线程，线程的处理速度主要与cpu的核心数有关，也就是核心数决定了能够同时处理的线程数，
            当线程数超过核心数时，多余的线程并不能同时被处理，但是多线程很适合IO密集型任务，因为IO密集型任务的大多数时间在等待
            操作，而非用cpu进行计算，因此临时创造的线程就是为了能够从队列中取出更多任务，避免过多的任务等待相应的时间过长导致
            系统判定失败，这在IO密集型任务中可以让申请数变多，使cpu的空闲时间减少，但是这在计算密集型任务中并不能提高处理速度，只是让更多任务在线程中进行等待。
    关于具体代码的语义：
        Condition(mutex)在锁的基础上给一个条件变量，每个Condition对象维护自己的等待队列，里面存放阻塞的线程
        wait(time)等待直到其他线程调用该等待队列的notify()或者时间到达time,并且把锁释放出去，允许其他线程获取（对应的sleep()则是强制等待一段时间）
        调用_not_empty.wait()，给_not_empty维护的队列添加一个阻塞的线程
        调用_not_full.wait()，给_not_full维护的队列添加一个阻塞的线程
        相应的调用_not_empty.notify()，唤醒它维护的队列中的一个阻塞的线程
        _not_empty和_not_full共用一个互斥锁
